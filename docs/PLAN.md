# PLAN — этап «Прозрачность агрегации»

Действия текущего этапа. Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` сделано,
`[!]` заблокировано или отменено. Переписывается при закрытии этапа.

Цель этапа: привести поведение бота в соответствие с правилом агрегации, записанным
в [weather-providers.md](weather-providers.md) — пользователь должен видеть, когда
источники расходятся, и получать значения по провайдерам там, где сводка ненадёжна.

## Действия

- [~] Вывести значения по провайдерам в сообщение прогноза. Поля `conflict`,
  `rainProbSpread`, `rainMmSpread` уже считаются в `aggregateSourceSummaries`, но
  дальше лога не идут; нужен ещё список источников после отбрасывания выбросов.
- [ ] Предупреждать о сильном расхождении источников для ближних дат.
- [ ] Для плановых поездок дальше семи дней предупреждение не показывать, а значения
  по провайдерам приводить всегда: дальний прогноз слаб сам по себе, расхождение в нём
  ожидаемо. Здесь задействовать `daysUntil` — функция написана и не вызывается.
- [ ] Держать блок с провайдерами вне LLM-редактуры: он содержит числа и названия
  источников, то есть ровно то, что запрещает валидатор в `polishForecastWithLlm`.
- [ ] Покрыть форматирование тестами, вынеся его отдельным модулем: `src/bot.js`
  ничего не экспортирует и тестами не покрывается.

## Вне этапа

- Реализация давно описанного, но не сделанного правила про усреднение близких
  значений — оно уже работает в `aggregateSourceSummaries`.
- Новые провайдеры погоды: список кандидатов и причины отказов — в
  [weather-providers.md](weather-providers.md).
