# PLAN — этап «Прозрачность агрегации»

Действия текущего этапа. Обозначения: `[ ]` не начато, `[~]` в работе, `[x]` сделано,
`[!]` заблокировано или отменено. Переписывается при закрытии этапа.

Цель этапа: привести поведение бота в соответствие с правилом агрегации, записанным
в [weather-providers.md](weather-providers.md) — пользователь должен видеть, когда
источники расходятся, и получать значения по провайдерам там, где сводка ненадёжна.

## Действия

- [x] Вывести значения по провайдерам в сообщение прогноза. `aggregateSourceSummaries`
  отдаёт наружу список источников после отбрасывания выбросов — поле `sources`.
- [x] Предупреждать о сильном расхождении источников для ближних дат. Признак —
  готовое поле `conflict`.
- [x] Для плановых поездок дальше семи дней предупреждение не показывать, а значения
  по провайдерам приводить всегда: дальний прогноз слаб сам по себе, расхождение в нём
  ожидаемо. Задействована `daysUntil`.
- [x] Держать блок с провайдерами вне LLM-редактуры: он приклеивается после
  `polishForecastWithLlm`, поэтому валидатор редактуры его не касается.
- [x] Покрыть форматирование тестами, вынеся его отдельным модулем:
  `src/forecast-details.js` и `test/forecast-details.test.js`.

Этап закрыт. Следующий задаёт владелец; до этого файл не переписывается.

## Вне этапа

- Реализация давно описанного, но не сделанного правила про усреднение близких
  значений — оно уже работает в `aggregateSourceSummaries`.
- Новые провайдеры погоды: список кандидатов и причины отказов — в
  [weather-providers.md](weather-providers.md).
