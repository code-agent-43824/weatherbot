# ROADMAP

Куда идёт WeatherBot. Документ долгоживущий: он про направление и порядок этапов,
не про текущее состояние — состояние в [STATUS](STATUS.md).

## Продукт

Telegram-бот, который отвечает мотоциклисту на один вопрос: ехать сегодня на мотоцикле
или нет, и не попадёт ли он под дождь по дороге. Не «прогноз погоды», а решение:
короткий вывод по маршруту, собранный из нескольких независимых источников.

Два вида сценариев, у пользователя их может быть несколько одновременно:

- **регулярный** — ежедневный маршрут дом → офис → дом, с учётом того, что возвращаться
  нужно на том же мотоцикле;
- **плановый** — поездка в один конец на конкретную дату.

## Принципы, определяющие развитие

- **Факты и вердикт детерминированы.** Языковая модель допускается только к
  формулировкам; см. «Settled decisions» в [CLAUDE.md](../CLAUDE.md).
- **Несколько независимых источников важнее одного точного.** Расхождение между
  источниками — это сигнал пользователю, а не шум, который надо спрятать.
- **Бесплатные источники без карты — по умолчанию.** Платный провайдер подключается,
  только когда риск по биллингу ограничен; см. [credentials.md](credentials.md).
- **Минимальный стек.** Node без зависимостей; новая библиотека или инфраструктура —
  решение владельца (§9 свода).

## Этапы

1. **MVP.** Диалог настройки, геокодирование по России, сбор погоды по трём точкам
   маршрута, агрегация по окнам утро/день/вечер, расписание и мгновенный `/forecast`.
2. **Качество источников.** Подключение провайдеров с ключами, кэш ответов, отбрасывание
   выбросов, устойчивость к падению отдельного провайдера.
3. **Прозрачность агрегации.** Показать пользователю, когда источники расходятся, и на
   чём основан вывод. Текущий этап — см. [PLAN.md](PLAN.md).

Дальнейшие этапы задаёт владелец; пока их нет, этот список не додумывается.
