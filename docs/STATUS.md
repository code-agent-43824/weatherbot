# STATUS

Состояние проекта на 2026-09-05. Один экран, перезаписывается.

**Версия:** `0.1.0` в `package.json`. В строке `USER_AGENT` (в `src/bot.js` и
`.env.example`) стоит своя версия — `WeatherBot/0.2`; две версии живут отдельно.

## Что проверено в этой сессии

- `npm run check` проходит: `node --check src/bot.js` + восемь тестов
  (`test/non-overlapping-runner.test.js`, `test/forecast-details.test.js`), все зелёные.
- Линтера, форматтера, сборки и CI-workflow в репозитории нет. Зависимостей нет,
  `node_modules/` не создаётся.
- Свод правил `AGENTS.md` лежит в корне, `CLAUDE.md` подключает его импортом.

## Что работает по коду

- Диалог настройки обоих сценариев, `/forecast`, `/scenarios`, `/stop`, `/reset`,
  `/intro`, кнопочная клавиатура, регистрация списка команд в Telegram.
- Сбор погоды по трём точкам маршрута из семи провайдеров; падение любого из них
  не роняет прогноз. Без ключей работают Open-Meteo, MET Norway, 7Timer.
- Предупреждение о расхождении источников и значения по каждому источнику в сообщении;
  для плановых поездок дальше семи дней — без предупреждения, но со значениями.
- Отбрасывание выбросов по медианной оценке риска, кэш ответов до 5 минут,
  дедупликация плановых отправок через `lastSentDate` и `createNonOverlappingRunner`,
  миграция старых пользователей в `migrateUserState`, удаление просроченных поездок.
- Сериализация записей в файл через promise chain (`saveChain`): concurrent-вызовы
  `saveStore` не теряют данные и не повреждают файл.
- Graceful shutdown: при `SIGTERM`/`SIGINT` цикл polling прерывается,
  `store` сохраняется, процесс завершается корректно.
- Разбиение длинных сообщений: текст свыше 4096 символов режется по `\n`
  и отправляется несколькими `sendMessage`. Клавиатура — только на последнем.
- `bot.js` сокращён с 1399 до 631 строк, выделены модули
  `datetime.js`, `telegram.js`, `geocode.js`, `weather.js`, `aggregate.js`.
- Retry с backoff: до 2 повторных попыток при сбое провайдера (1с, 2с).
- LRU eviction для `weatherCache`: лимит 100 записей, самая старая
  удаляется при превышении.
- Outlier filtering: порог отбрасывания выбросов снижен с 3 до 2.
- LLM validation: проверка количества строк (±2) и сохранения «сухо».
- `forecastLogs` и `addressLogs` обрезаются до 500 записей: файл данных не
  растёт без ограничений.

## Известные расхождения

- Расхождение правила агрегации с кодом закрыто, см. [PLAN.md](PLAN.md) и `JOURNAL`.
  Из полей агрегата в сообщение по-прежнему не выводятся `severeVotes`,
  `rainProbSpread`, `rainMmSpread` и `originalSourceCount` — они остаются в
  `forecastLogs`; отдельного правила, которое этого требует, нет.

## Не проверялось

- Продакшен. По `README.md` сервис живёт на сервере Oracle и разворачивается из `main`;
  ни доступа к серверу, ни логов деплоя в этой сессии не было. Доехали ли последние
  коммиты до сервера и рестартовал ли процесс — не подтверждено.
- Реальные ответы провайдеров: сетевые вызовы в этой сессии не выполнялись, все выводы
  сделаны по коду и документам.
- Связка блока источников с `buildForecast`: сам блок покрыт тестами, а четыре строки
  в `src/bot.js`, которые его вызывают, — только `node --check`. `src/bot.js` ничего
  не экспортирует, автотестом это не берётся; первая живая проверка — сообщение бота.
